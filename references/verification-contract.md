# Skill 验证与执行边界

规则验证必须检查是否会把 approved_schematic 的 PCB 工作重新升级为电路审查，不以测试数量代替实际执行效果。修改纯 Skill 时做文档、引用和例子验证，不为验收文字修改操作用户 PCB，也不重编译未变的 MCP。

## 回归场景

| 输入情况 | 应有行为 | 不应出现 |
| --- | --- | --- |
| 已确认原理图，已有元件和网络 | 读取本批定位/连线数据后放置 | 查器件手册、逐脚电气复审、完整 BOM 审计 |
| 中心传感器的面和中心已给定 | 按给定位置放置、保持可调整 | 补查磁钢、气隙、偏心和封装高度 |
| 同一组件/网络已读入缓存 | 复用，改变后只更新受影响对象 | 每个 changeEpoch 都重读整板 |
| 要放去耦电容 | 根据原分区和已有连接贴近服务电源脚 | 先验证容值是否符合手册 |
| 空网络、NC 或陌生料号 | 沿用源电路，正常执行其他连接 | 自动补接、查保留脚、创建电气待确认清单 |
| 草案布局或普通保存 | 可逆落位；runDrc:false | 全板 DRC、组合门、锁定前审批表 |
| 本批移动成功且工具已独立读回 | 使用返回结果继续 | 再做全板 pinmap 或相同对象的重复核验 |
| prepare 已返回有效 guard | 原计划加 guard 执行 | 再跑 validate、改参数但复用旧 guard |
| 写入结果未知/部分成功 | 只对账精确对象，保留成功前缀并续后缀 | 整批重放或退回 S0 |
| 用户中途移动或实际 ECO | 保留新位置，刷新对应端点和旧铜 | 按旧计划覆盖用户操作 |
| 已出现的局部短路/间距错误 | 处理对应区域 | 忽略实际错误，或扩展为全板电气重新设计 |
| 完成布线、铺铜和丝印 | 最终 PCB DRC、连接、回路和文件检查 | 把未委托的气隙/高度/器件性能审查加入放行 |
| 只要求改 Skill | 验证文档与示例，安装并读回新版本 | 为证明 Skill 生效改动正在工作的 PCB |

## 保留的工具防错

写入目标必须是当前精确工程/PCB；expected 旧值来自真实对象，guard 与未改动计划绑定。网络不因移动改变，修改丝印不改组件身份。读取错误不能填成空数组；未知结果不能宣称成功；DRC 失败不能报零；生产文件必须真实生成。

客户端的单位、底面镜像、孔形量化、原生 Polyline、特殊焊盘等适配由 MCP 实现；模型需要了解操作字段，不需每次重新证明适配算法。格式或回执确实有错时只查相关技术参考并做最小修复。

## 自动检查范围

包内 tests 检查入口长度、模式优先级、取消复审/早期 DRC、保留网络回路与接口规则、模板无审批字段、引用有效及 JSON 示例结构。维护时再将操作速查的完整计划交给当前 MCP validatePlan 校验器离线验证，不连接编辑器。

这些测试验证文档契约和计划格式，不证明模型将来每轮都会正确执行，更不是板级电气或制造验证。没有独立模型行为复测就不报告“彻底不会再拖延”或行为通过率。

安装后读取当前激活的主文档及至少一个引用，运行同样的静态检查。若只改 Skill，保持 MCP 实现版本不变；新版插件仅更新该 Skill 与必要版本/入口描述，不能伪称工具功能已升级。

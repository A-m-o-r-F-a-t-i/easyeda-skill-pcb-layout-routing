# 开发验证范围

测试验证当前 17 工具接口、MIL 参数、对象解析、批量顺序、部分成功、未知写入、数据总览、SVG、DRC、导出和文档一致性，不构建布局评分或运行期审批。模型决定设计和分析时机。

MCP 回归覆盖任意角度、同批移动后按新焊盘布线、大批量输入、原生拒绝、响应丢失、底面镜像、异形焊盘、密集标签、MIL 几何/连通/功能组测量、外部 DSN 到 MIL 的归一化和原子文件输出。源码测试同时确认旧计划、profile、别名与不可达模块已经物理删除。

Skill 测试覆盖 approved_schematic、MCP 优先、MIL-only、17 工具名称、无兼容参数、工程知识保留、示例类型和相对链接。静态测试不证明模型未来每次都能画好 PCB。

真实客户端只读、模拟写入与真实测试副本写入分别报告。工具或 Skill 维护不在生产板上写测试对象。真实写入需要明确测试副本；自动化测试通过不冒充全部实机编辑通过。

4.1 新增显式铜带、旋转孔阵列和焊盘组朝向回归，覆盖凹区、孔洞、NPTH 切断、真实成铜/仅边界、必经单孔与并联孔、未知几何、指定截面、跨进程回执、重复请求、未知结果和保存失败。执行恢复只保证同一持久请求不被再次派发，未完成原生动作仍需事实核对。

## 反思条款与场景回归

　　Skill 7.2 的文档回归检查完整功能通道、参考层职责、主路与检测分支、全层候选孔位、自动分段后的定向读取、实际铜形和报告范围，并保留MIL-only、大批量操作与MCP优先。

　　`tests/review-scenarios.json` 是通用决策场景，供条款覆盖检查和人工审阅；`tests/reflection-guidance.test.mjs` 检查所引用章节、关键决策和禁止的错误推论。它们是静态文档回归，未运行模型行为评测，不证明实际布局质量提升。

　　开发验证不为重演碰撞在实板上放孔，不重跑生产板DRC或上电。后续实际模型设计效果应在获得授权的PCB任务中单独验证。

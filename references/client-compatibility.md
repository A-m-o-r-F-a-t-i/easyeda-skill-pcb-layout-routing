# 原生数据差异与使用范围

这里记录已知客户端表现，适配属于 MCP 实现细节。常见 PCB 操作仍优先 MCP，不因为下面的原生细节重新生成 API 脚本。

## EasyEDA Pro 4.1.60

- 元件引脚接口与 canonical Pad 接口可能给出不同孔字段。总览优先使用同一物理 ID 的 canonical 孔数据，原来源缺失时孔尺寸保持未知。表贴焊盘的残留孔字段不表示有实际钻孔。
- 已知 POLYGON 焊盘顶点可直接处于板坐标并已包含镜像、旋转。MCP 在已识别的坐标表示下绘图，不再叠加焊盘位置变换；未知版本保留数据缺口。
- 独立焊盘坐标和外形可能量化到 0.1 mil；ROUND 可能返回两个相等尺寸。工具报告实际值，不把任意量化扩大为设计容差。
- 板框使用原生 Polyline，圆形使用 CIRCLE 表达，不用大量短线冒充。原生 REGION 规则只使用 API 已定义的枚举；客户端拒绝时返回原生错误，不静默改为另一种禁止规则或源文件重写。
- 某些实际铺铜路径与普通图元采用不同数值尺度。只有已知数据表示才换算为统一坐标，其他表示在 SVG 中注明未覆盖。
- 原理图导入请求可能仍需原生确认界面。既有 MCP 同步适配处理确认与实际结果；返回 true 不能单独当作 PCB 已改变。没有选择性 ECO 能力时不声称跳过指定差异。

## 其他已知行为

部分旧客户端局部重铺可能影响非请求铜区，结果应报告实际影响。某些 scalar get 在对象删除后仍给出占位对象，对象枚举和实际执行结果更适合确认身份。原生 BBox 包含图形范围，不能代替本体尺寸。

未知结果先使用回执或局部对象读取；不盲目重复创建。源代码回滚不恢复 PCB，测试、原生只读与真实写入的验证范围分别报告。

# 客户端实测兼容性与工具证据

## MCP 1.4能力选择

先核对实际工具索引、实例版本和目标工程范围。1.4包含22个类型化工具，增加原生工程/文档备份与指定PCB标签页渲染截图。试验实例的工程允许列表不扩大到其他工程，不能为取得新工具重启另一线程使用中的旧实例。缺少某工具时查询同一公开API的已验证入口，保留同样的目标和读回保护。

| 操作 | 优先工具 | 必要条件与验收 |
|---|---|---|
| 实验前原生备份 | `pcb_export_backup` | 工程/PCB/窗口精确绑定，目标为新的绝对`.epro`路径，父目录已存在；字节长度、ZIP签名、本地读回校验通过；重要恢复试验另验档案完整性与编辑器恢复 |
| 当前PCB画布截图 | `pcb_capture_view` | BETA渲染API，显式使用目标文档tabId，无切窗、改层、缩放副作用；生成新的PNG，逐图确认实际内容，画面外或隐藏层仍未验证 |
| 全接口丝印数据 | `pcb_inspect_silkscreen` | 同时读取独立文字和元件属性；分页必须汇总，页内包围盒相交不能替代跨页或真实字形检查 |
| 试验清理/人工介入核对 | `pcb_compare_snapshots` | 同一工程、文档和单位，完整图元数组，另比较netlist、layers和constraints；缺少类别不能补成空数组 |

原生文件备份与截图只写明确的本地新文件，不覆盖旧文件，不上传。文件导出无权限时保留错误，不以渲染截图或检查快照代替原生备份。文件中可能含工程私有资料和字体，发布工具源码或Skill时排除这些运行产物。

## 3.2.186约束组行为

下列是此客户端版本的适配规则。工具请求的alpha始终使用0～1，RGB使用0～255。该版本原生创建接口的alpha按0～255字节解释，而读取返回0～1；MCP针对确切版本进行转换及量化后读回。未知版本不默认套用该适配。

原生网络类、等长组的增删成员操作会将组颜色改为不透明黑色。默认保留颜色：当前颜色不同且不能保留时，工具在写入前拒绝。明确接受颜色变化时才传`allowColorReset:true`。新建无颜色偏好组可直接使用不透明黑色，使后续成员维护没有额外颜色变化。工具不能通过放宽读回比较掩盖此副作用。

颜色可以显式为`null`。已存在的组必须携带真实旧颜色与成员，不能把颜色缺失当作`null`。删除等长组后，相关网络规则可能仍留下默认长度容差字段，组列表恢复为空不足以说明试验已恢复。清理时比较完整规则与图元，对有恢复要求的隔离实验采用已验证的原生副本恢复，不在生产板上无依据整表覆盖。

## 孔径读回的规范来源

4.1.60 的 getAllPinsByPrimitiveId 在导入封装上可能返回未规范化孔字段，而 pcb_PrimitivePad.getAll 对同一物理ID返回正常mil尺寸。孔径不得依据经验统一乘10：先核对两来源的针号、网络、层和位置，再采用规范焊盘的孔、偏移、孔旋转及金属化字段，原值保留为 componentPinHoleRaw。规范来源缺失时 holeReadback.verified=false，保留尺寸未知。表贴层焊盘可能仍保存非生效hole字段，机械审查使用 physicalDrill，并以实际钻孔文件复核。圆槽长度按总长处理，刀具行程需扣除孔径。

## 焊盘对的地址格式

4.1.60 实测自定义焊盘可返回 `["POLYGON", [x, y, "L", ...]]`，顶点已经处于板坐标系并包含器件镜像和旋转；按焊盘 x/y/rotation 再变换会二次移动铜形。仅在原生边界与顶点范围一致后采用该适配。直线环按真实顶点保留凹口，未知命令或无效环拒绝。孔数据不明时采用外轮廓作为保守间距包络并保留孔/铜连通验证缺口。

原生焊盘对组使用下列地址，不把所有焊盘内部ID一概传入：

| 焊盘类型 | 地址 | 核验 |
|---|---|---|
| 元件焊盘 | `R1:1`，即位号与焊盘号 | 当前位号唯一，实际元件包含该焊盘号 |
| 游离焊盘 | 真实游离焊盘primitiveId | 在游离焊盘API返回对象中存在 |

位号被改成功能名或存在重复时，不能用坐标猜测它指向哪个器件。工具拒绝歧义地址，设计过程读取唯一对象并重新规划。为隐藏丝印不应改变电气位号值。

## 实时DRC与查询降级

`pcb_capabilities`只报告入口存在。3.2.186的实测中实时DRC启停接口返回false，读取前后也为false，不能宣布已开启或已关闭。工具报告action、before、result和after供诊断，并继续用可工作的原生完整DRC检查。原生DRC返回零错误也不替代项目自定义的45°几何、载流和可读性验收。

原生区域查询可能抛出“单多边形验证不通过”。类型化图元与原生包围盒读取可以构成备用查询，必须报告原错误、降级路径及遗漏类型。明确权限拒绝不使用降级路径继续同一被拒动作。

## 旧状态与起始页

启动页可能返回`documentType:0,uuid:"0"`，不一定返回null。`pcb_open_target`的旧文档期望值必须直接来自发现结果。

历史属性文字可能累积到超过3600°的有限rotation。完整expected保留原始读回值，不能为通过验证擅自将旧值归一化并当成真实状态。新设rotation仍限制范围。只改文字显示时保留位号、父对象、层、位置及其他未要求字段。

## 证据和来源

这些规则区分官方签名与指定客户端的实际返回。兼容性结论按版本限定；单次试验不外推到所有客户端、字体、工艺或设计。

- 官方`SYS_FileManager.getProjectFile/getDocumentFile`：原生File导出，需要对应导出权限。
- 官方`DMT_EditorControl.getCurrentRenderedAreaImage(tabId)`：BETA指定标签页渲染图像，省略tabId会采用最后输入焦点，因此本工具必须显式传入。
- 官方`PCB_Drc.createPadPairGroup`示例：元件焊盘地址为`Designator:PadNumber`，游离焊盘使用ID。
- 详细官方签名保存在通用API Skill相应类文档，设备测试数据和工程备份保留在任务工作区，不嵌入Skill包。

## 原生恢复后的派生数据

原生源码写回不构成整个编辑器状态的原子恢复。覆铜缓存可能先为空再异步生成，网络规则也必须单独比较。恢复后等待派生填充稳定，并核对对象、网表、规则和保存状态。角度读回可能将-90.00000000000001归一化为-90，快照比较仍保留该原始差异，由数值分析区分浮点往返与真实移位，不删除差异或伪造基线。

3.2.186的覆铜重建返回对象有身份异常实测；报告请求边界、返回对象、实际填充关联与未知项，不能因返回某个对象就认定每块铜已更新。填充非空不代表热连接或载流验收。

| 观察 | 已采用的处理 | 验证边界 |
| --- | --- | --- |
| 覆铜 scalar get 对不存在 ID 仍返回对象 | getAll 按精确 ID 验证修改和删除 | 非空对象不再视为存在证明，完整列表与数组查询分别核对。 |

### 局部重铺、焊盘对与ECO读回

第二轮局部重铺曾修改非请求边界的Poured。MCP 1.5对本客户端默认拒绝部分请求，明确接受副作用时传allowCollateralRebuild=true，并检查nonTargetFillChanges；整板请求仍需读回每块实际关联。临时对象清理后仍可能保留派生填充再生成差异，不能称逐字节恢复。

焊盘对成员添加成功后，客户端可能反向返回端点。执行器对无方向焊盘对归一化，反向重复添加不再发出原生写入，删除使用现场原始顺序。自身配对仍拒绝，差分对正负语义不变。

原生 importChanges=true 只表示客户端接受了导入请求。V4.1.60 实测会继续打开 dlgShowImportChanges 确认窗口；Gateway 扩展上下文可在精确 PCB 身份守卫下定位该窗口唯一的 data-test="Apply Changes" 控件并执行确认。执行器随后等待确认控件消失，再读取两次稳定 PCB 快照；只有对象或网表状态真实改变才返回 imported=true。窗口根节点可能在完成后保留为空，因此不能用 DOM 根节点是否存在判定导入完成。生产同步还会把原生 netlistComparison 的网络差异与 PCB 实际组件引脚网络读回交叉核对；V4.1.60 在已正确导入时可能把 PCB 侧网络成员返回为空，这类假差异只在实际 padNumber/net 成员与原理图成员完全一致时消除。真实成员不一致仍保留为差异。

## 原生禁布写入与断点接续

4.1.60 原生文档重建可能将 COMPONENT.angle 的270°改为-90°。执行器仅将有限角度相差整周的情况视为几何等价，并返回 normalizedAngles，不能声称原始记录完全未变。位置、网络、其它属性或无法解释的记录变化仍拒绝，错误附必要的对象和字段信息，不自动回滚。

重试前重新准备当前状态。所有目标区域已实际存在且层、锁定、禁止对象类型与几何完整匹配时，执行器返回 alreadyApplied=true、wrotePCB=false 并执行受保护保存，不重复源码写入或重新生成同一备份。部分满足、未知几何、目标不符或旧来源守卫不成立时，仍需读回并重写剩余计划。

## 显式路线的极短尾段

4.1.60 实测，一条45°续接因端点差0.1mil生成极短尾段，该尾段未在独立读回中出现，前面的有效线段已真实创建。局部计划生成器为六mil及以上走线采用显式的一mil最短段预检，这是避免多余折点的保守生成策略，不是客户端或板厂最短线长承诺。预检失败时返回具体段端点，不静默吸附原引脚。部分成功后按当前对象生成剩余计划，只修改明确决定调整的连接点。

## 板框 Polyline、空网络与断点接续

4.1.60 实测，`PCB_PrimitiveLine.create` 不能可靠创建 `BOARD_OUTLINE`，闭合外圆、安装孔和内槽应使用单个原生 `PCB_PrimitivePolyline`。板框对象写入后可能返回 `net:null`，而计划语义为无网络空字符串；该等价仅用于板框身份核验，不扩展到铜网络。原生 `getAll('', layer)` 可能过滤掉这些 `null` 网络对象，执行器必须全量枚举后本地比较层、锁定、线宽与循环等价的完整闭合路径。

创建调用超时、代次变化或独立读回失败时，先读取当前全部 Polyline 并按几何确认已完成对象。只生成尚缺外圆、孔或槽的续作计划，每项缩为独立批次并保存；不得重放完整机械计划。旧 Gateway 不识别新增 `polylines` 读取类型时，MCP 使用精确工程、PCB 和窗口身份经 Bridge 做只读枚举，同时保留 generation、change epoch 与 source hash 守卫。

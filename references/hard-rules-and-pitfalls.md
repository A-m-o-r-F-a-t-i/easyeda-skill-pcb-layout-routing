# PCB 布局布线硬性规则与已验证踩坑

本文件记录 EasyEDA PCB 任务中应长期复用的工程规则、失败模式和恢复方法。它只处理 PCB，不替代原理图、电路计算、器件数据手册或制造商最新能力。采用 `approved_schematic` 时沿用已确认电路和封装，不为普通 PCB 续作主动查找数据手册；原生 DRC 仍按阶段门执行。

## 1. 设计优先级

发生冲突时按以下顺序决策：

1. 电气安全、器件绝对额定值和故障后果；
2. 机械装配、连接器方向、安装孔和禁布区；
3. 可制造性、跨组件碰撞和 DRC；可信库封装内部报告按明确规则豁免；
4. 电源回路、回流连续性、信号完整性和热设计；
5. 可布通性与维修调试；
6. 板面积、外观和排列整齐。

板更小不能覆盖前五项。元件都能塞进板框只证明面积容纳，不证明布局完成。

## 2. 开始写入前建立最小真实状态

读取时同时接纳最新有效人工修改。完整协作规则见[live-collaboration.md](live-collaboration.md)，默认丝印标准见[silkscreen-usability.md](silkscreen-usability.md)。已授权的同板全差异ECO不受最初列举修改项限制，保留明确排除和PCB侧独有机械/布局信息。

第一次板框、孔槽或局部布局写入前，只读取保护当前动作所需的真实状态：

- 当前工程、PCB UUID、窗口 ID、文档类型和单位；
- 当前板框、安装孔、孔槽、禁布区和用户明确的机械输入；
- 本次将创建、移动或连接对象的 primitive ID、位号、层、坐标、旋转、锁定状态、封装和焊盘网络；
- 本次影响区域内的已有铜、孔槽、铺铜和用户固定对象；
- 直接决定当前写入安全性的层角色、单位和制造下限。

全板器件属性、完整 BOM 和所有数据手册不因 PCB 作图自动读取或补齐；只有用户另行明确委托电路或装配审查时才进入相应工作流。全量原生 DRC 在 `LAYOUT_DRC`、`ROUTING_DRC`、`POUR_DRC` 和 `FINAL_DRC` 阶段运行，不要求在空白板第一次机械写入前执行。扩大 PCB 对象读取范围必须能改变下一项动作；否则继续板上工作。

**禁止**：根据截图猜焊盘网络，根据位号顺序猜连接关系，根据缓存 ID 盲写，或在原理图与 PCB 同步状态未知时批量替换封装。

**同样禁止**：在板框尚未建立时，为与当前机械动作无关的耐压、温升、完整料号或生产文件执行全板审计；把工具测试通过、BOM 导出或源码修复当作布局完成；因一个局部对象待确认而停止所有无依赖区域。

## 3. 布局硬规则

### 3.1 机械与接口

- 外接接口位于板边且朝外时，同时检查连接器塑胶本体、插拔方向、线束弯折、锁扣、螺丝刀和对接件空间。
- 连接器焊盘在板内不代表本体未越界。使用现有封装实体、装配外形或用户已提供的尺寸检查；不要为普通 PCB 续作主动查找数据手册。
- 底层连接器的视觉镜像会改变左右关系。放置前按“从实际插接方向观察”的针脚顺序复核，不能只看顶视图整齐。
- 安装孔周围同时设置铜、元件和走线禁区。金属螺丝、垫片和外壳的实际直径优先于孔径。
- 板框缩小必须晚于接口、关键链路和高密度扇出的试布线。布局时保留接口功能与逐针网络的信息带，缩板后重新执行碰撞、可布通与标识可读性检查。

### 3.2 功能链路与器件顺序

布局按完整链路，不按位号或元件类别堆放：

```text
外部接口 → ESD/浪涌保护 → 滤波/限流 → 收发器或 MCU
电源入口 → 反接/浪涌保护 → 输入电容 → 开关器件 → 电感 → 输出电容 → 负载
MCU 引脚 → 串联电阻/排阻 → ESD → 接口
```

- ESD 器件靠近外部入口，泄放路径短、宽、少过孔，不能让浪涌先穿过板内长线。
- 串联电阻靠近其抑制对象。源端终端靠近驱动端，接口侧限流/保护按实际目的放置。
- 排阻旋转后应让源侧和目标侧分别朝向两端，避免每根网络在器件附近交叉。
- 收发器同时满足逻辑侧短线和总线侧直接出线。不能只照顾 MCU 一侧，把 CANH/CANL 绕过整板。
- 去耦电容按“电源过孔/电源面 → 电容 → 电源脚”和“电容地端 → 就近地过孔”的实际高频回路放置。距离近但回路绕行仍属于错误布局。

### 3.3 高密度器件扇出

- MCU、BGA、细间距 QFP 每排焊盘先保留直出段，再允许转向或落过孔。
- 保护阵列、去耦、排阻和接口不能横向封死主扇出面。
- 过孔落点属于布局资源。预留成组落孔区，不能等所有器件塞满后再寻找零碎孔位。
- MCU 旋转由高优先级网络所在边、接口方位和电源/时钟回路共同决定。器件文字朝正不是旋转依据。

## 4. 层叠和参考面硬规则

- 层数、铜厚和层角色在布线前写入设计约束。不得一边布线一边隐式改变层角色。
- 四层默认起点为 L1 信号/器件、L2 完整 GND、L3 电源/低速、L4 信号。六层优先提供两个连续参考面，使高速信号换层后仍有邻近回流。
- GND 平面保持连续。电源分区、禁布区和密集反焊盘不得把关键回流切断。
- 信号跨层时，若参考面发生变化，在换层过孔附近提供地缝合过孔或等效回流通道。
- 不在被指定为 GND/电源面的内层随意穿普通信号。确需穿越时先更新层角色并复核整板回流。
- 二层板无法提供完整内层平面时，优先保持一面尽量连续的地铜，减少长距离切割和狭窄地颈。

## 5. 电源与高电流硬规则

- 先定义持续电流、RMS、峰值、故障电流和允许温升，再定线宽、铜厚和过孔。
- 使用 `current-carrying-reference.md` 的层别与通孔表。制造最小线宽不等于电流线宽。
- 开关电源按已确认原理图、现有分区和网络关系识别热回路。输入旁路、功率开关、续流路径和输出回路面积必须最小。
- SW 节点满足导通面积后不额外扩张，远离时钟、复位、模拟输入和连接器长线。
- 高电流路径优先走外层宽铜或铺铜。换层按单孔分配值和不均流系数计算并联孔数。
- 铺铜能力由最窄颈、焊盘热连接、过孔入口和器件引脚决定。宽大铜面中间出现 0.2 mm 颈缩时，整条路径按 0.2 mm 计算。
- 正向路径和回流路径同时规划。只加宽电源、不处理地回流会把压降、噪声和热集中转移到地端。

## 6. 信号和布线几何硬规则

### 6.1 布线顺序

```text
电源/大电流
→ 开关热回路、时钟、复位、模拟参考
→ 差分或成对网络、CAN、USB 等接口
→ 高边沿总线和 SPI
→ UART/I²C/QEI/PWM
→ 普通 GPIO
→ 铺铜、缝合、丝印和收尾
```

先布普通 GPIO 会占用关键通道，最终只能用大量过孔和绕线补救。

### 6.2 转角、线段和过孔

- 铜线只使用水平、垂直和 45°段，直角处用倒角点。禁止两个独立线段在同一端点拼成隐藏 90°。
- 同方向连续线保持为一个逻辑路径。API 可拆成图元，但设计模型仍保存完整起终关系。
- 过孔用于必要换层，不用于掩盖器件方向错误或接口顺序错误。
- 关键网络每次换层都检查参考面、回流过孔、过孔 stub 和邻近铜面切割。
- 差分或成对网络保持同层、共同参考、近似一致的过孔结构和拓扑。不要为了视觉等长加入无意义蛇形。

### 6.3 禁止自动寻路

本工作流不调用 EasyEDA 自动布局或自动布线。MCP 只执行模型已经明确给出的器件位置、点列、层、线宽、孔位和铺铜边界。任何缺失路径保持未规划状态，不由执行器猜测。

### 6.4 几何预检与原生铜形状

- 预检结果必须声明覆盖的对象。只读取线段、焊盘和过孔的检查器不包含原生泪滴、填充铜、实际覆铜结果、区域规则或板边约束，未覆盖项必须保留为待验收。
- 每批实际写入后做独立读回，不重复运行整板 DRC；到布局、关键/整板布线、重铺铜和最终阶段门时执行原生 DRC。预检通过而阶段 DRC 报告泪滴或填充间距冲突时，读取该错误涉及的真实对象，调整孔位或已规划点列，再读回并复检。不能以基本图元之间的间距通过代替原生结果，也不能通过删除检查规则消除报错。
- 派生铜形状会随连接、孔位和器件变化而更新。完成局部修改后重新获取它们，避免用修改前的泪滴、铺铜结果或图元 ID 判定当前设计。

### 6.5 角度验收的统计范围

- 分别统计普通二线段折点、焊盘中心、过孔中心和分支节点。报告计数时注明是线段对数量还是唯一节点数量，不混用两种口径。
- 普通二线段 90°折点为零，只说明该类折点检查通过。焊盘、换层和分流节点仍须逐点检查是否产生多余直角折返、急角或不必要支路，不能把排除这些节点后的结果称为全板无直角。
- 另行检查每段铜线是否水平、垂直或 45°。没有 90°折点不代表所有斜线都符合角度规则。按实际坐标精度设定容差，记录容差和是否排除了完全包含在同网焊盘内的短线。
- 铺铜边界、实际填充边缘和器件固有焊盘形状分别验收。不要把封装本身的矩形焊盘当作走线直角进行改形。

### 6.6 铺铜存在、连通与层别

- 对每个 POUR 边界分别核对 Poured 是否存在、实际填充片数、网络、层和连接对象。所有边界都有非空填充，不等于所有电源和地网络已经闭合。
- 同一网络出现多个填充片时，检查各片是否经同网导线、金属化通孔或过孔接到主干。需要列出未接入主干的焊盘或局部连接组，再用原生未连接结果复核，不能仅按填充片数判失败或通过。
- SMD 焊盘仅能直接连接所在铜层。多层视图中的投影重合不构成跨层连接，只有确认金属化的通孔或过孔才能参与层间连接判定。
- 解析 API 返回的覆铜路径前，用已知板框、焊盘和过孔坐标交叉核对比例与坐标原点。派生路径与普通图元的数值尺度可能不同，不把一次客户端实测比例当成全部版本的恒定单位。
- 重建铺铜后重新检查连接、孤岛和最窄颈。旧版本的非空填充计数或截图不能覆盖随后新增走线、移动过孔和器件产生的变化。

## 7. 布线不顺时的布局回调

布局先于布线，但不是一次性冻结。正确循环为：

```text
初始布局 → 关键网试布 → 局部调整 → 关键网完成 → 分区冻结 → 普通信号 → 必要的局部回调
```

满足任一条件时回调布局：

- 关键链路需要三次及以上贯通换层；
- 实际路径显著超过直接可达路径，且绕行由器件朝向或分区阻塞造成；
- 焊盘无法按规则直出，或任何合法过孔落点都会封死相邻网络；
- 高电流路径出现小于计算宽度的不可消除颈缩；
- 成对网络被迫长距离分离或跨越参考面缝隙；
- 去耦、晶体、终端或 ESD 无法进入有效位置；
- 尚未开始普通网络，主通道已经被关键网之外的铜占满。

移动已经参与布线的器件时：

1. 读取当前元件状态、焊盘与相关铜；
2. 明确 `affectedNets`；
3. 使用 `copperPolicy: "replan"`，或仅在完全未布线时使用 `"unrouted"`；
4. 移动后重新读取焊盘中心；
5. 删除或重规划受影响铜，不假定铜会自动正确跟随；
6. 完成后复查邻近分区；若本次改变使已有阶段结果失效或到达里程碑，重跑对应 DRC。

## 8. EasyEDA API/MCP 已验证踩坑

| 现象 | 根因 | 正确处理 |
| --- | --- | --- |
| 线段创建成功但后续 ID 失效 | EasyEDA 可能拆分、合并或替换图元 | 每批写入后按网络和几何读回，不长期缓存图元 ID |
| 线宽、孔径读回略有变化 | API 内部单位为 mil，输入可能量化 | 计划显式声明 `mm` 或 `mil`，执行器统一转 mil，验收用容差比较 |
| TypeScript 文档有枚举，Bridge 运行时没有全局枚举名 | Bridge 只注入 `eda`，不保证枚举变量全局存在 | 使用经文档核对的命名映射；不要把运行时缺枚举误判为权限问题 |
| 一个超长内联命令没有可靠结果 | 调用封装过宽、响应超时或状态不确定 | 先独立读回，再把显式操作写入本地 `easyeda-pcb-plan/v2`，校验后分批执行 |
| 重试后出现重复线或重复孔 | 未确认上次是否部分成功 | 创建操作按几何幂等检查；缺失返回值一律先读状态 |
| 删除/修改了错误图元 | 只凭旧 ID，没有核对网络和旧属性 | 修改/删除必须携带完整 `expected` 旧状态，执行器先比对再写 |
| 移动元件后铜线错连或悬空 | 铜不会保证按设计意图跟随器件 | 组件操作要求 `copperPolicy` 与 `affectedNets`，移动后重规划 |
| 创建了铺铜边界但画面无实际铜 | POUR 边界与重铺/填充是不同阶段 | 使用`pcb_rebuild_pours`重建并读取Poured；非空填充后仍检查连接、孤岛和最窄颈 |
| DRC 为零但板仍不合格 | DRC 不验证热载流、回流、接口方向、装配和视觉质量 | 同时检查已给定载流规则、网表/未连接、回流、截图、装配和保存读回验收 |
| Bridge/截图短暂超时就被判定断联 | 临时网络、窗口或客户端卡顿 | 等待并指数退避重连，扫描 49620～49629，确认服务身份和 EDA 窗口后续作业 |
| 器件看似无重叠但无法焊接或插拔 | 只检查焊盘中心/包围盒，未检查已有实体和操作空间 | 使用现有封装装配外形、丝印、已有 3D/用户尺寸和插拔方向复核；缺失资料不触发主动查手册 |
| 四层或六层板被当作每层同样铜厚 | 混淆层数和铜厚 | 从实际叠层读取外层/内层铜厚，默认多层内铜 0.5 oz 不可自行改写 |

## 9. 批量执行与恢复规则

- 10 个以上同区域图元或重复操作优先写入本地计划文件。计划内容保持可读、可审查和可复现。
- 布局/重布局省略 `batchSize` 时，不超过 100 个展开操作默认作为一个完整轮次；小型少元件板先计算完整布局再一次提交，大板按功能区使用 40～100。布线等其他阶段默认 24；只有真实超时、响应过大或客户端异常时降到 8～24。
- 每个布局轮次必须得到 `padOverlapGate=CLEAR`（无相关对象可为 `NOT_APPLICABLE`）。`PAD_OVERLAP_BLOCKED`、`BLOCKED` 或 `UNVERIFIED` 时只修正当前轮，不能开始下一轮；该门不替代布局整体成形后的原生 `LAYOUT_DRC`。
- 每批执行前核对 PCB UUID/文档类型，执行后独立读回，成功批次立即保存。
- 一个批次中途失败时保留已完成结果和精确失败操作。下一次从读回状态继续，不整批盲重放。
- 同一技术形式失败两次后停止继续放大该方案。先读取真实状态，再切换等价的小批 MCP、Bridge 公共 API 或可见 UI 操作；只要新路径能绑定精确目标、独立读回并保留工程备份，就可以用于板框、孔槽、器件放置等明确动作。
- 浏览器优先用于视觉审查和无公开 API 的编辑器功能；当 MCP/API 兼容层持续故障时，也可执行范围明确、可截图且可由 PCB 对象读回验证的单步或小批操作。禁止无法独立核验的长序列鼠标自动化和整板黑盒批量修改。
- 一次最小复现和最多两轮同根因修正后仍失败，立即隔离该动作并继续其他区域。只有故障阻断所有板上进展时才升级公共工具链；不得顺带重构无关快照、渲染、安装器或 Gateway。

## 10. 分阶段冻结与验收门
